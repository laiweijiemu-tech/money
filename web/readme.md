## 项目定位

本项目是一个专为**短线打板选手**和**龙头战法践行者**量身定制的轻量级股票盯盘系统。它摒弃了传统财经软件“大而全”的冗余信息，聚焦于\*\*“主线题材”**与**“核心龙头”\*\*，旨在通过自动化的数据监控与策略预警，帮助交易者在瞬息万变的短线市场中，实现“盘前定方向、盘中抓买点、盘后做复盘”的高效实战闭环。

## 核心亮点

- **极致的龙头战法垂直化**：不做信息百货超市，只做短线客的“特种兵军火库”。所有功能围绕“主线挖掘、连板梯队、分歧回封”等核心实战逻辑深度定制。
- **高度定制化的策略雷达**：独创“分歧转一致回封雷达”与“板块联动预警”，能够自动化监控炸板回封、弱转强等关键买点，解决人工盯盘反应慢的痛点。
- **零成本的数据自由**：通过巧妙组合免费且响应迅速的 HTTP 数据源，以零成本搭建了一套接近付费级别的实时盯盘系统，性价比极高。
- **轻量高效的跨平台体验**：基于标准 HTTP 协议与轻量化架构，无需安装庞大客户端，在电脑浏览器、平板或手机上均可随时随地高效盯盘。

## ️ 五大核心功能模块

### 1. 热点挖掘与复盘中心（宏观导航）

- **盘中实时热点榜**：实时监控竞价抢筹与盘中5分钟异动，快速锁定当前资金攻击的最强主线。
- **情绪仪表盘**：量化展示昨日涨停溢价率、连板晋级率，直观判断市场赚钱效应与亏钱效应。
- **盘后复盘报告**：自动归类涨停原因，梳理龙虎榜知名游资动向，确立当日绝对主线。

### 2. 龙头选股池（目标锁定）

- **智能初选**：基于最强主线板块，自动筛选出连板高度最高、率先涨停的个股。
- **核心标签展示**：直观标注“身位龙（最高板）”、“中军（容量核心）”、“先锋（最早涨停）”等辨识度标签。
- **辅助参考展示**：在列表中直观展示总市值与流通市值，辅助判断个股的拉升阻力，但不作为绝对筛选门槛。

### 3. 盘中盯盘雷达（实战扳机）

- **高频盯盘列表**：3秒级高频刷新核心池个股的实时价格、涨跌幅与封单金额。
- **专属战法信号**：精准捕捉“炸板回封”、“弱转强秒板”等信号，并触发声光强提醒。
- **板块联动确认**：监控龙头拉升时是否有板块小弟集体跟风，辅助确认打板安全性。

### 4. 持仓风控哨兵（纪律保障）

- **动态止损监控**：实时监测持仓股是否跌破5日线或触及最大回撤阈值，触发即报警。
- **炸板离场预警**：监控涨停封单骤减或频繁炸板情况，提示利润回撤风险。

### 5. 系统配置与数据管理（后台支撑）

- **数据源与策略配置**：灵活配置免费接口轮询频率，支持微调选股与预警的触发阈值。
- **预警日志回溯**：记录每一次雷达触发详情，为策略优化与历史复盘提供数据支撑。

## 龙头选股逻辑体系

本平台的选股池严格遵循短线游资的实战审美，**以题材情绪为核心，以市值为辅助参考**：

- **题材与情绪（核心门槛）**：必须处于当前市场最强主线（板块涨停潮），具备政策或产业变革的颠覆性逻辑。
- **连板与身位（硬指标）**：优先筛选市场最高连板股（空间龙）与板块内率先封板的先锋（时间龙）。
- **筹码与辨识度（实战细节）**：偏好启动价格较低（如10-30元）、自由流通市值适中（如10亿-60亿）、换手充分的个股，剔除缩量庄股与超级大盘股。

## ️ 技术架构方案

- **后端框架**：采用 **FastAPI (Python)** 作为核心服务层，负责行情抓取、策略计算、预警分发与日志落库。利用异步协程机制同时拉取多只股票与多个板块数据，降低串行请求造成的延迟，适合盘中高频盯盘场景。
- **前端框架**：采用 **Vue 3 + Echarts** 构建轻量化实时看盘界面。Vue 负责状态管理与组件联动，Echarts 负责分时、板块热度、连板梯队、预警日志等可视化展示，便于快速识别主线与龙头异动。
- **数据存储**：采用 **SQLite** 作为本地核心数据库，按“基础资料表、股票池表、板块热度表、预警日志表、复盘结果表”进行拆分存储。其部署成本低、迁移简单，足以支撑单机版或轻量私有化部署。
- **数据通信**：整体基于标准 **HTTP 协议** 对接外部免费数据源，内部通过统一接口服务向前端输出标准化 JSON 数据。盘中使用秒级轮询，盘后切换为低频补数与复盘任务，在保证响应速度的同时控制限流风险。
- **调度方式**：采用“**盘中高频、盘后低频、开盘前预热**”的三段式任务调度。开盘前完成股票池、题材池和基础资料预加载；盘中聚焦核心标的高频刷新；盘后再回补公告、龙虎榜和题材归因数据。
- **稳定性设计**：在接口层加入超时控制、失败重试、本地缓存、备用源切换与异常日志记录，避免单一免费接口波动导致整套系统失效，确保盯盘和预警在关键时段持续可用。
- **前后端分离架构**：将后端服务层与前端展示层分离，实现独立部署与扩展。后端负责数据处理、策略计算与预警分发，前端负责用户交互与数据展示。这种架构模式为系统维护与升级提供了灵活性。
- **代码分层**：将后端服务层分为“数据抓取层”、“策略计算层”、“预警分发层”、“日志记录层”等，每个层负责不同的功能模块。前端展示层分为“用户界面层”、“数据展示层”、“交互层”，负责处理用户输入、数据展示与用户交互等。

## 免费 API 接口方案

为了兼顾**零成本、低延迟、可维护**三项目标，推荐采用“**主接口负责速度、备用接口负责兜底、本地缓存负责减压、统一适配层负责解耦**”的组合方法。核心思路不是依赖某一个完美接口，而是通过多源协同，把免费数据源拼接成一条足够稳定的盘中链路，优先选择响应快、字段稳定、市场验证较多的数据源。

### 1. 行情主接口层（盘中高频核心）

- **东方财富 Push2 / Quote 系列接口**：适合承担个股快照、涨跌幅、成交额、盘口、板块列表等核心数据抓取任务，通常响应较快，字段也相对丰富，适合作为主行情源。
- **腾讯财经 QT 接口**：适合作为备用快照源，返回轻量、请求成本低，适合在主接口异常或限流时快速兜底。
- **新浪财经实时接口**：适合补充分时快照、基础行情字段校验，也可作为第三优先级冗余源。

### 2. 策略数据层（题材、涨停、异动、复盘）

- **东方财富相关榜单接口**：可重点用于涨停池、板块热度、资金流向、个股异动、概念成分股等题材型数据抓取，是“主线题材 + 龙头挖掘”的核心来源。
- **同花顺/财联社/公开资讯页抓取**：适合补充新闻、题材驱动、公告摘要、盘后热点解释等文本类信息，但应作为低频数据源使用，避免高频依赖页面结构。
- **龙虎榜/公告/研报类公开页面**：用于盘后复盘信息补全，适合做定时抓取与本地落库，不建议盘中高频轮询。

### 3. 开发封装层（提升接入效率）

- **AkShare**：免费、社区活跃、封装广泛，适合快速验证接口可用性与字段结构，可作为原型期和盘后分析模块的数据抓取工具。
- **Tushare 免费积分接口**：适合承担日线、财务、基础资料、交易日历等低频数据，不建议依赖其做超高频盘中盯盘主链路。
- **自研适配器层**：建议在项目内部统一封装 `provider -> normalize -> cache -> strategy` 流程，避免前端和策略直接耦合第三方字段。

### 4. 推荐的数据源分工

- **3秒级盯盘数据**：优先使用东方财富主接口，腾讯财经作热备。
- **板块热度与涨停梯队**：优先使用东方财富榜单类接口，必要时增加页面抓取补充题材解释。
- **个股基础资料**：使用 AkShare 或 Tushare 做低频同步，每日开盘前更新一次即可。
- **复盘与资讯补充**：使用公告、龙虎榜、新闻资讯页做定时抓取，统一写入 SQLite。

### 5. 接口设计建议

- **统一输出模型**：无论上游来自哪个接口，后端统一转换为标准字段，如 `code`、`name`、`last_price`、`change_pct`、`turnover`、`seal_amount`、`theme`、`leader_flag`。
- **本地缓存机制**：对低频数据增加 1 分钟到 1 天不等的缓存时间，对高频行情仅缓存数秒，减少重复请求和被限流风险。
- **熔断与降级策略**：主接口连续失败时自动切换备用源；若备用源字段不足，则只保留核心行情与预警能力，确保系统可用。
- **异步批量抓取**：利用 FastAPI + `httpx` 异步并发请求，按股票池批量拉取，避免单股串行请求带来的延迟累积。
- **盘中与盘后分时调度**：盘中只保留高价值核心接口高频轮询，盘后再做板块归因、龙虎榜、公告、资金流等补全。

### 6. 实战落地建议

- **首选组合**：`东方财富主行情 + 腾讯备用行情 + AkShare低频补全`，这是免费、速度、开发效率三者之间较均衡的方案。
- **原型期优先**：先把“个股快照、板块热度、涨停池、预警日志”四类接口跑通，再逐步补充分时、资讯和复盘数据。
- **注意事项**：免费接口大多属于非正式开放资源，字段和限流策略可能变化，务必加入超时、重试、缓存、降级与日志监控，避免盘中因单一源失效导致全系统不可用。
